# /Clarify Workflow

This workflow is used when there is ambiguity in the user's request, contradictions in the project specification, or technical uncertainties that require user input.

## Steps

1. **Identify Ambiguity**
   - Pinpoint specific areas where requirements are unclear.
   - Look for conflicts between the [Project_Spec.md](../spec/Project_Spec.md) and new requests.

2. **Formulate Options**
   - Instead of just asking "what should I do?", present 2-3 viable technical paths.
   - Explain the pros and cons of each path (e.g., Performance vs. Complexity).

3. **Present to User**
   - Clearly state the problem.
   - List the proposed solutions.
   - Ask for a decision or further details.

4. **Update Specs**
   - Once clarified, immediately update the relevant specification files in `.agent/spec/` to reflect the decision.
   - Ensure the "Single Source of Truth" remains accurate.
